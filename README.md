# Структура проекта

- `/modules`: модули приложения
- `/app`: инфраструктурные вещи, не связанные с бизнес-логикой
- `/shared`: общие компоненты, функции, стили для всего приложения

# Решение для UI - PrimeVue unstyled model

## Документация

- https://primevue.org/theming/unstyled/

## Плюсы

- без борьбы со встроенным css (удаляются все встроенные стили компонентов, оставляя только структуру и логику)
- гибкий Pass Through API (позволяет прокидывать классы и атрибуты внутрь встроенных DOM-элементов)
- сохраняется функциональность PrimeVue
- можно использовать любую дизайн-систему (tailwind, bootstrap, собственные классы)

## Минусы

- компонент не работает из коробке (ВСЕ надо стилизовать, в т ч анимации, hover/focus/active/disabled состояния)
- неполная документация по unstyled mode
- PT API местами неудобен (надо изучать внутреннюю структуру компонента, искать нужные pt-ключи, силизовать вложенные элементы вручную)
- для получения полноценного компонента нужно комбинировать несколько (вместо указания пропса с именем иконки инпуту - добавлять компонент иконки и позиционировать самостоятельно ее)
- вся настройка стилей лежит в объекте внутри компонента, в т ч стилей размеров, что засоряет script
- слабая документация

## Вывод:
Не подходит в нашем случае, т к не является готовой ui-библиотекой, заставляя, по сути, делать большую часть работы с 0, что увеличит время разработки.
